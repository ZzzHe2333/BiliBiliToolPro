# Zzz-Bili 青龙任务互斥锁

同一个青龙容器中的 `Zzz-Bili` 订阅任务默认串行执行。

原因：多个任务如果同时执行 `dotnet run`，会共享同一个仓库的 `obj/bin` 输出目录，可能出现 PDB/程序集被另一个进程占用；同时并发运行多个 B站任务也会在短时间内增加 API 请求密度。

## 默认行为

- 启动订阅任务时先获取全局 `Zzz-Bili` 任务锁。
- 环境检查/首次安装也在锁内执行，避免多个任务同时执行 `apt`、`apk` 或 .NET 安装。
- 一个任务结束后，下一个等待中的任务再继续。
- BiliTool 主进程结束后立即释放锁；青龙系统通知不占用任务锁。
- 优先使用系统 `flock`；精简 Alpine 镜像没有 `flock` 时自动使用原子 `mkdir` 兼容锁。
- 兼容锁会检查 PID，并自动清理明显的异常退出残留锁。

## 最长等待时间

默认最多等待：

```text
3600 秒
```

可通过青龙环境变量调整：

```bash
Zzz_BILI_LOCK_WAIT_SECONDS=3600
```

该值必须为非负整数。设置为 `0` 表示锁被占用时立即失败，不等待。

等待超时后任务返回非 0，不会强行与正在运行的任务并发。
