# B币券临期提醒与自动充电

本 fork 的青龙订阅中，`Zzz-Bili 免费B币券充电任务` 可以每天运行，但不会每天消费 B 币券。

## 判定规则

1. 只有年度大会员参与。
2. `Zzz-Bili 领取大会员福利任务` 成功领取“年度大会员每月赠送的B币券”时，记录实际领取时间。
3. 预计到期时间固定按：`领取成功时间 + 30 天`。
4. 免费 B 币券充电任务每天检查一次：
   - 没有可信领取记录：不自动充电；
   - 距预计到期超过 5 天：普通记录，不提醒、不自动充电；
   - 进入预计到期前 5 天且尚未进入最后 48 小时：如果仍有余额，输出 `B币券临期提醒`，该 Warning 会进入现有青龙任务通知；
   - 进入最后 48 小时且余额不少于 2：执行自动充电；
   - 进入最后 48 小时但余额为 1～不足 2：无法满足充电最低余额，输出 Warning 提醒手动使用；
   - 余额为 0：无需处理；
   - 已超过预计到期时间：不使用陈旧记录自动充电；
   - 本期已自动充电：后续检查直接跳过。
5. 充电目标仍按账号级配置 > 全局配置 > fallback UID 的顺序决定。

## 为什么每天检查

“每天检查”只是为了不会错过 5 天提醒和最后 48 小时的自动处理窗口。真正的充电请求只有在最后 48 小时并满足余额条件时才会发出。

青龙订阅的免费 B 币券充电任务默认每天 12:00 运行。Web/Quartz 默认配置也使用每天 12:00 检查。

## 通知

临期提醒使用程序日志的 Warning 级别，不会被青龙包装脚本判定为“部分失败”。

由于 Zzz-Bili 任务结果默认通过青龙系统通知发送，因此提醒会直接附在当天免费 B 币券充电任务的现有通知正文中，不需要额外配置单独的推送渠道。

## 状态文件

青龙环境下按 B 站 UID 分文件保存到：

```text
/ql/data/config/zzz-bilibili-tool/bcoin-coupon-<B站UID>.json
```

如果设置了 `QL_DATA_DIR`，则使用：

```text
$QL_DATA_DIR/config/zzz-bilibili-tool/bcoin-coupon-<B站UID>.json
```

状态文件位于订阅仓库目录之外，因此重新运行订阅、重新拉取 Git 仓库不会删除它。

Web 环境保存到应用 `config/zzz-bilibili-tool/`；其他 Console 环境保存到应用 `.state/zzz-bilibili-tool/`。

## 旧券说明

升级到本版本前已经领取、但程序没有记录领取时间的 B 币券，不会猜测到期日期后自动消费。这样做是为了避免误把新券或其他余额提前充掉。下一次通过本 fork 成功领取 B 币券后会自动建立可信状态。
